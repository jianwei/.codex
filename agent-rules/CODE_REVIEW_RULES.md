# 全局代码评审经验与工程约束

本文件是全局代码评审规则的单一真源。后续用户提供的评审建议，应提炼为与具体业务无关、可跨项目复用且可验证的工程约束，并在这里去重维护。目标不是增加规则数量，而是持续减少缺陷、回归和评审不确定性，在提高代码质量的同时提升代码质量评分、PR 描述评分和综合评分。

## 评审建议归纳

处理用户提供的评审内容时：

- 以“建议”和“改进建议”中的可执行修复与预防机制为主要依据；问题描述只用于识别触发条件和风险。
- 先判断建议影响的评分维度：正确性与安全、可维护性、测试可信度、兼容与交付、文档与可审阅性；优先沉淀能消除真实缺陷或同时改善多个维度的规则，不以堆叠形式化要求追求表面分数。
- 优先级依次为：阻止安全、数据损失和核心流程错误；降低边界与回归风险；收敛类型、状态和单一真源；补强测试、观测、部署与评审证据；最后才处理不影响行为的局部风格问题。
- 每条规则统一写成“触发条件 + 应采取动作 + 可验证结果”，省略文件名、行号、页面、接口、字段、产品文案和具体流程。
- 写入前与全文比对并合并同义项；同一根因只保留覆盖面最完整的一条规则。跳过无法跨项目复用、收益无法验证、纯主观偏好或可能引入过度设计的内容。规则与已确认的项目事实或用户明确约束冲突时，以后两者为准。
- 完成后按“新增或增强的规则 → 对质量和评分的直接收益 → 已被现有规则覆盖或未采纳的建议”输出简洁总结，使后续改进重点和评分提升依据都可追踪。

## 状态与生命周期

实现和评审异步操作、调用链调整或资源管理时，逐项确认：

- 用独立状态表达“请求中”与“最近成功”；异步去重以成功结果为准，提前标记仅用于并发防重且须在失败时回滚，使相同输入可以重试。变量命名、写入和清理时机必须与该生命周期一致。
- 用户主动触发且可能失败的操作，应对成功和最终失败提供可区分反馈；可恢复失败还须提供重试、返回或重新开始等明确下一步，主路径与降级路径全部失败时不得静默结束。可取消交互须区分约定的取消结果与异常，仅正常取消可静默结束，并明确第三方拒绝即取消的约定；验证各结果对应的反馈、恢复入口与状态。
- 阻断页面操作的加载提示须有确定的结束机制：同页操作或路由跳转在完成、失败或取消时关闭；整页跳转须为被拦截或跳转失败提供超时或其他可恢复兜底。多个入口共用相同提示合同时复用具名配置；测试断言关键阻断参数及失败后的恢复，并在目标环境验证提示的实际消失时机。
- 同一错误若同时配置自动跳转和用户操作弹层，须按既有交互合同明确唯一主路径；保留兜底弹层时确保自动处理失败后仍可见、可操作。验证自动成功、自动失败和手动操作各路径，不保留永远来不及展示的分支。
- 调整调用链时只保留当前场景必需的调用；移除入口或分支时，同步处理其错误路径、加载状态、状态变量、观测口径及缓存、数据关联、结束信号等隐含依赖，验证保留入口仍按原合同工作。
- 创建 timer、listener、observer、subscription、abort controller、轮询、动画帧或重试循环时，建立对称且统一的 acquire/release；持续任务须有完成条件、超时或最大次数以及取消路径，用户中断或宿主销毁时立即停止，并在 `finally` 或统一清理中复位状态。多个操作重复相同的取消、加载和清理流程且语义一致时，可收敛为共用包装，并验证各操作的成功、失败与取消路径仍独立正确。封装事件型 Promise 时覆盖成功、错误、超时和取消的 settle 路径，并清理监听器与加载状态。删除触发入口前先盘点剩余创建路径，仅当资源不再可能创建时删除清理逻辑，并验证无无限循环、泄漏和孤立清理代码。
- 并行或可独立触发的异步流程使用独立取消域；只有合同明确要求同时终止时才共享 `AbortController` 或取消令牌。验证取消、重启或销毁其中一个流程不会误伤验证码、保存、轮询等其他在途操作，取消结果也不会被包装成普通业务失败。
- 同一阶段内彼此独立的远程请求不应无依据地串行等待；根据接口限流、浏览器连接数和数据规模选择并发或有上限的任务池，并明确部分失败、结果顺序、取消和重试合同。验证多项输入时总耗时不会线性放大，单项失败不会造成未处理拒绝或错误覆盖，宿主销毁时全部在途任务可停止。
- 轮询的间隔、总超时、退避和终态以服务合同、旧版基线或真实延迟数据为依据，并集中配置；超时后的跳转、提示或继续查询须明确为业务决策。验证弱网、长响应、持续处理中、终态、取消和超时分支，避免任意短超时制造假失败。
- 包装外部命令或子进程时，保持原命令已支持的参数、退出码与终止信号合同；显式处理启动失败并以非零状态退出。验证正常执行、参数透传、启动失败和中断时不会静默挂起或遗留子进程。
- 从响应式输入派生且可能随输入变化的值，使用 `computed` 或项目等价机制保持同步；仅合同明确为不变量的值可一次计算，并通过命名、类型、注释或测试固定其静态语义。
- 同一次逻辑判断依赖“当前时间”时，在操作开始处获取单一时钟快照并贯穿本次计算；验证循环、排序或归约不会因多次取时产生边界漂移。
- 保存供取消或返回时恢复的状态前，明确快照的捕获、更新和失效时机；按恢复目标保存独立值或稳定标识，避免浅拷贝共享引用和过期快照，并验证中途修改后的恢复结果。
- localStorage、sessionStorage 等持久化流程状态须绑定订单、用户或任务等稳定身份，只保存恢复流程所需的最小数据，并定义版本、消费、过期、终态清理及条目或容量上限；过期清理由应用或流程入口兜底触发，不能只依赖某个理想入口或存储引擎被动执行，成功、取消和放弃等终态主动删除对应数据。恢复时先完成深层结构、身份一致性及关键数值有限性校验，不一致或污染数据按上下文失效处理；包含个人或订单信息时优先选择满足需求的最短存储生命周期。验证跨订单、刷新、重复进入、直接深链、成功、取消和超时后不会复用旧流程状态、长期残留敏感信息、耗尽存储配额或生成 `NaN` 提交数据。

## 单一真源与数据语义

实现和评审可复用规则、领域值或数据转换时，逐项确认：

- 新增或复制规则前先搜索现有实现和实际消费者；两个及以上消费者共享同一合同时建立单一真源，统一输入和计算口径，纯逻辑使用公共 TypeScript 工具函数，响应式状态或生命周期使用项目既有 composable 模式。多入口共享校验及后续交互时收敛为同一调用路径，已取得判定结果不再重复执行等价校验；集中测试各入口结果一致且无冗余计算。单一消费者不为假想复用提前抽象。
- 状态码、类型码、哨兵值、占位值及重复出现的领域字面量，使用最小合理作用域的具名常量或枚举；被多个 mock、fixture 或开发配置引用的样例标识及清单也应维护单一真源，验证各处使用同一数据。枚举与类型分支显式列出已知值，并为未知值定义拒绝、忽略或降级策略，不用“其余值”代替合同。条件中的每个字段须对结果产生可追踪影响，无效条件应移除，隐含约束通过命名、注释或测试说明。
- 集合判断直接用 `every`、`some`、`includes` 等结构化谓词表达，避免拼接后匹配分隔符字符串；同一语义状态影响标签、颜色、可见性或交互时，先规范化为单一结果再派生全部展示属性，验证各属性在空集合、单项、混合项、全匹配及未知状态下保持一致。
- 一项数据通过数组关联多个实体时，按完整集合的交集或包含关系判断，不以首项代替整体合同；验证多段、多票、顺序变化和部分匹配不会漏选或误选。
- 遗留协议要求字符串替换时，先确认匹配单位是整值、独立词还是子串，再按该边界一次性转换；验证普通词不会误命中，替换产物不会被后续规则再次替换。
- 为兼容外部系统而保留异常编码、隐式类型转换或历史缺陷时，先验证接收方的实际解析合同，并在代码中记录可追溯依据、适用范围与迁移条件；验证特殊字符及接收方升级后的行为，不将偶然产物当作长期协议。
- 相关信息保存在同一对象中，或通过稳定且唯一的 key 关联；渲染 key 优先采用不可变 ID 或由适配层生成的稳定 ID，不使用数组索引或可能重复、变化的展示字段。去重、排序或过滤后不依赖平行数组的原索引，有意丢弃关联时在类型、命名或注释中明确边界。
- 外部字段的声明、映射和消费保持一致；接口或 props 允许多种原始类型时，在边界规范化为单一内部类型后再比较或分支，或直接收窄合同，并为每种允许输入以及缺失、未知输入定义可验证语义，不依赖隐式转换的偶然结果。外部合同含历史拼写错误或非常规字段名时，在传输边界保留真实 wire key，再映射为语义正确的内部名称，并注明合同来源和兼容期限；未经上下游同步及契约测试不得只在类型中单方面“纠错”。发现未消费字段时先核对接口合同、mock 和所有调用方，明确权威值、优先级和回退规则，确认废弃后再从完整数据链移除，不以单个调用点未使用为由修改公共合同。跨页面、版本或存储交接的键名与数据结构视为公共契约，通过共享常量、组合类型和类型化适配器维护单一真源，并以契约测试或真实联调验证双方一致。
- 同一状态可由路由参数、持久化存储、服务端数据、宿主注入或默认值等多个来源提供时，先定义来源优先级、有效值判定、合并与失效规则，再在单一适配边界解析；缺失、空值、解析失败或低优先级旧值不得无条件覆盖已确认的有效值。验证各来源单独存在、同时存在、冲突、为空、无效及读取失败时均选择合同规定的结果。
- 路由名称、路径、参数键、兼容默认值和页面元信息视为同一导航契约，在路由定义附近集中导出具名常量或类型化 location 构建器；内部跳转优先使用命名路由及结构化参数，不在调用方重复拼接路径或散落兼容查询值。同一入口只保留一种权威生成方式，URL 字符串辅助函数仅在确有外部链接消费者时保留并基于同一契约生成。历史拼写、旧路径或特殊参数必须记录兼容来源、不可变边界和迁移条件，支持时用 alias 或显式迁移兼容而非直接“纠错”。验证路由改名、参数缺失、旧书签或深链、页面标题及内外部入口不会发生静默漂移。
- 公共函数或组件在读取选项前先规范化缺失、`null` 和非法输入，并在执行副作用前校验当前模式的必填字段；互斥模式使用可辨识联合、独立入口或等价合同表达有效参数组合和优先级，不接受会被静默忽略的冗余参数。验证空选项、字段缺失、各合法模式及冲突参数不会抛出意外异常、产生 `undefined` 输出或执行错误动作。
- 修改共享 API 的参数名、必填性、模式或默认行为时，先全局盘点实际调用方，并选择兼容层、明确迁移或版本化方案；同步更新类型、文档、示例和调用方，验证旧合同按声明兼容或明确失败，新合同覆盖所有使用入口。公共 API 变更不能只依赖局部编译通过或单个调用点验证。
- 已知结构的接口模型应显式声明实际字段及其必填性；宽泛索引签名或 `unknown` 仅隔离在确有动态扩展需求的边界，并注明用途，不能覆盖核心模型而使属性拼写和合同漂移失去类型检查。控制流结果使用可辨识联合或枚举表达状态，不将哨兵字符串与用户文案混在同一返回类型中；验证调用方对全部状态进行穷尽处理。
- 组件输入及其嵌套对象默认由上游拥有，子层通过事件或本地状态提出变更，不直接依赖原地修改输入对象触发响应；确需共享可变模型时明确所有权并使用与嵌套变更匹配的响应式机制。验证单项变更可独立更新，且结果不依赖无关列表重算或隐式时序。
- 两处及以上 UI 具备相同结构和交互合同时，才抽取小型子组件或具名插槽，并验证完整交互合同不变；仅视觉相似或单一消费者时保持局部实现。
- 组件内纯数据适配或格式化达到职责独立、可单测或可复用的程度时，抽到 adapter/util；同一输入和条件的重复查找收敛为一个派生结果，不变集合与配置提升为模块常量，昂贵转换只在输入真正变化时重算，并验证各消费者结果一致及重算边界不变。
- 新增或修改的中间计算结果必须被返回、渲染、记录或用于控制流；原消费者被移除时同步删除仅为其服务的解析、格式化和异常捕获链。确需暂时保留时关联可追踪任务并说明恢复条件，验证不存在执行后无任何可观察作用、却让维护者误判已有反馈或处理的逻辑。
- 从多项数据生成单一展示值时，先确定取首项、逐项展示或聚合的合同，再遍历全部适用项；数值单位及格式按输入合同处理，验证多项差异、缺失值和单位变化时结果仍正确。
- 由多个数值字段共同决定展示或操作资格时，按完整合同判定，不以单个字段为零替代整体结果；验证主值为零而附加值非零等边界组合。
- 从远程集合中搜索、选择或校验实体时，不把固定条数的首屏结果当作完整数据集；按接口能力实现服务端搜索、分页加载、明确的“未找到”继续查询路径，或在产品合同中显式限制范围。验证目标位于边界页、超过默认上限、重复名称和空结果时不会被误判为不存在。

## 输入、安全与兼容边界

处理外部输入或兼容能力时，逐项确认：

- 将远程 URL 视为不可信输入；绑定链接或执行跳转前统一按合同校验协议、相对路径和域名，明确允许列表并拒绝 `javascript`、`data` 等可执行协议。高风险外部跳转须收窄可信来源和目标域名，不以 HTTPS 作为放行任意域名的唯一条件；相对地址应解析并规范化后校验最终导航目标，覆盖编码分隔符、反斜杠和控制字符等歧义输入。登录回跳、授权回调等重定向参数须由接收方在完整解码后校验最终协议、域名和允许路径，发送方编码不能替代开放重定向防护。路径与查询参数按 URL 合同构造，不依赖配置是否自带末尾分隔符；查询串用 `URLSearchParams` 或等价方式逐值编码不可信参数，遗留特殊转义须先确认协议且不能替代标准编码。非法值须 fail closed，并验证大小写、空白及 `&`、`=`、`#`、中文等输入不能截断或注入参数。
- 字符串跨页面或系统传递时，区分字符集编码、内容编码和 URL 传输编码：先按约定字符集生成字节，再执行 Base64 等内容编码；内容放入路径或查询参数时继续使用 Base64URL 或标准百分号编码，并确认接收方按相反顺序解码。验证中文、补充平面字符以及 Base64 中的 `+`、`/`、`=` 能完整往返，且不存在漏编码或重复编码。
- URL 编码只保证语法完整，不提供保密性；票号、身份信息、令牌及其他敏感业务参数不得进入 URL、浏览器历史或访问日志。遗留 JSONP/GET 合同无法避免时，最小化字段、缩短有效期并明确网关与客户端日志脱敏策略，验证特殊字符不会改变参数边界且日志中不出现可还原的敏感载荷。
- 向接口、存储或跨页面协议提交数据时，按目标合同显式挑选和映射允许字段，并限制键集合、嵌套深度、集合数量及序列化后体积，不直接展开表单、组件状态、缓存对象或接口响应；新增字段须经过同一映射边界才能外发。验证内部标记、展示字段、个人信息及服务端只读字段不会因上游对象扩展而被意外提交，污染缓存或异常大对象也不能生成超长请求或额外参数。
- 外部日期先按合同校验真实日期并规范化，再由同一结果生成显示文本和星期；区间还须校验先后顺序，不能用绝对值把反序转换为合法时长，日历天数按日期合同计算而非直接依赖固定毫秒数。日期上限优先采用合同规定的相对范围；固定截止日须说明来源并验证截止日之后的行为。非法日期统一降级，并验证允许格式、时区、夏令时和闰日等边界，避免对未校验值直接截取或交给 `Date` 隐式解析。
- 服务端、缓存或用户提供的富文本只有在确需保留格式时才能进入 HTML 渲染入口，并统一经过成熟的白名单 sanitizer；纯文本场景使用 `textContent` 或框架插值，不用正则剥标签或自行维护不完整的标签过滤器。所有进入同一 `v-html`、`innerHTML` 或等价 sink 的字段必须走同一清洗边界，禁止通过字符串模板拼入未清洗片段。验证脚本、事件属性、危险 URL、SVG/MathML namespace、注释、畸形标签和实体编码等攻击输入均不能执行，正常允许标签仍可展示。
- 图片、附件或其他二进制转换流程必须在迭代结束后验证目标后置条件，例如文件大小、尺寸、格式和质量；达到次数或质量下限仍不满足时返回明确失败，不把超限产物当作成功继续上传。输出格式根据目标环境能力与压缩特性确定，并验证超大文件、无损格式、透明图、转换失败、取消及兼容降级路径。
- 读写 localStorage、sessionStorage、缓存或其他外部序列化数据时，在统一适配边界确认底层同步性、序列化、TTL 与异常合同，并捕获解析、读写、删除及配额异常；读取结果显式区分不存在、无效、过期和存储不可用，写入失败返回或抛出统一的语义错误，避免各调用方重复且不一致地兜底。流程入口在执行副作用前校验必需的上下文标识，使“流程标识缺失或过期”与“业务保存失败”得到可区分的状态、提示和观测；可恢复缓存校验失败时清除坏数据并回源。整体 `as` 断言不能代替运行时形状校验，辅助数据损坏或存储故障须与主请求失败分开处理，避免被外层 `catch` 误归因。相关模型通过共享字段、组合类型或适配器复用结构，并验证语法错误、非法形状、缺失值、配额耗尽、底层 API 抛错与主流程错误均有可区分结果，避免平行类型漂移。
- HTTP 成功与业务成功分开判定；共享请求层须定义业务失败的错误合同，由调用方明确处理，不能仅凭 `data` 缺省把失败静默降级为正常空结果。业务拒绝与网络异常应提供可区分的反馈和不泄露敏感信息的错误码、类别等观测信息；若兼容合同要求业务失败后仍继续特定流程，应在调用处说明并测试，不得以宽松的响应校验掩盖该决策。验证传输失败、业务失败和合法空数据可区分。
- 下载或导出请求须同时定义“成功二进制”和“失败错误体”合同：先按 HTTP 状态与响应类型判断结果，失败响应即使以 Blob、ArrayBuffer 或文本承载，也应在请求或下载适配层按 Content-Type 安全解析为统一错误，并保留无法解析时的通用兜底；成功后再确认文件有效性并交付内容。服务端文件名按标准头部语法解析字符集与编码，解码失败可降级，最终移除路径分隔符、控制字符和平台非法字符并提供安全默认名；创建临时对象 URL 后按浏览器实际消费时机释放。验证 JSON/文本/二进制错误、空文件、缺失或畸形文件名、Unicode 与兼容下载路径均不会被保存为正常文件，且用户获得可区分反馈。
- 外部校验失败可能影响后续操作时，先按风险和产品合同明确阻断、重试或放行策略；若允许失败后继续，须记录可观测事件并说明约定，不能用空 `catch` 将异常伪装成校验通过。验证请求异常时的后续行为与观测结果符合合同。
- 环境域名与协议规范化集中在配置或 URL 适配边界，使用结构化 URL 解析、明确的主机名合同和白名单，不在业务 API 模块中用域名正则或字符串替换修补协议；配置缺失、HTTP 升级和新增环境须有显式策略，可变环境值通过可注入或可单测入口读取，避免模块初始化时固化状态。验证允许域名、近似域名、未知域名、端口、路径及各环境协议均按预期路由。第三方脚本地址与前端公开凭据按环境配置，并在提供方支持时设置适用的域名、来源限制和额外安全机制；仅在资源版本固定且可校验时评估 SRI。调试或 mock 路由只在开发环境启用，验证生产构建不会命中；前端公开凭据不得被当作可保密的服务端密钥。
- 跨窗口、iframe、WebView 或 Worker 传递消息时，发送端使用最小且明确的 `targetOrigin`，接收端同时校验 `origin`、`source` 与消息结构后再执行副作用；只有不含敏感数据且所有接收方均可信的公开广播才能使用通配目标，并记录理由。验证伪造来源、相似域名、非法消息类型和缺失字段均被拒绝，合法来源不因环境切换失效。
- 本地代理、调试工具或测试客户端默认连接隔离的非生产环境；需要携带 Cookie、令牌或调用写接口时，不得静默直连生产，目标须可配置，并通过显著启动提示、显式确认、只读限制或等价保护暴露风险。验证默认配置不会修改生产数据，生产目标无法因遗漏环境变量而被意外选中。
- 不可信值参与文件名、路径、存储键或资源定位前，按允许格式校验并阻断路径分隔符、遍历语义及越界定位；验证异常输入不能逃逸预期命名空间且有安全回退。
- 任何生产代码、测试、脚本或配置采用新语法或 API 前，核对 engines、锁定依赖、CI 镜像和实际执行环境；共享模块还须明确浏览器与服务端边界，使全局对象访问、入口 guard、类型声明、lint globals 和测试环境采用同一合同。宿主可能在模块加载或组件创建后注入全局能力时，通过统一适配器明确等待、刷新或一次性快照语义；需要响应后续注入的状态不得在初始化阶段固化为普通常量。验证服务端导入与渲染、全局对象缺失、初始化前注入和延迟注入均不会抛错或长期停留在过期状态。调用平台桥接、剪贴板等专属能力前显式检测能力，缺失时按合同执行 Web 或通用降级；无可用降级时给出明确失败反馈并记录可观测信息，仅执行埋点后静默结束不视为处理。支持与不支持分支均须验证。最低受支持版本或目标运行时不兼容时提供替代实现，并在该环境验证。
- 废弃 API 仅可作为有明确旧环境需求的隔离降级路径：现代 API 保持主路径，统一适配器记录适用环境、保留原因和移除条件，并验证废弃能力未扩散到业务调用方。
- 测试、fixture 与 mock 只使用确认可入库的虚构或充分脱敏信息；提交前按敏感字段和仓库规范复核，验证样例不能还原真实身份、凭据或业务秘密。

## 构建与部署契约

- 依赖清单或锁文件变化时，核对清单声明、锁定版本、完整性信息及实际依赖图一致，并审查直接与关键传递依赖的 peer/optional 约束、安装脚本、弃用和运行时要求；纯锁文件变更须说明产生方式并排除无关依赖漂移。在与 CI 一致的运行时和包管理器版本下执行干净安装，再按影响范围运行类型检查、测试和生产构建；验证升级后的插件、构建器、测试框架及样式工具组合可共同工作，而不以 patch/minor 标签推定兼容。
- 修改构建工具生成的 HTML、资源标签或外部脚本注入时，优先使用工具提供的结构化扩展与属性序列化能力；必须按文本匹配产物时，对升级敏感的格式假设增加构建期断言。验证入口脚本、样式和预加载资源无遗漏、重复加载或错误路径。
- 新增静态资源使用能表达用途且稳定的名称，并在合入前检查所有引用目标已纳入变更、路径大小写与部署文件系统一致，同时检查实际引用、内容重复、文件体积和目标格式；大图按画质合同压缩或选择更合适的格式，SVG 等可执行文档格式须检查脚本、外链和事件属性。通过生产构建验证无缺失、未引用或重复资源进入产物，优化前后视觉与兼容性符合目标环境。
- 容器构建按依赖清单、锁文件、源码的变化频率分层复制，并用构建上下文排除测试产物、编辑器配置及其他非构建输入；验证仅修改源码时依赖安装层可复用，最终镜像不携带无关文件。
- 对要求可复现发布的基础镜像使用不可变版本或 digest；运行服务按部署平台提供与真实服务路径一致的健康探测，并明确超时、重试和启动宽限。验证镜像来源可追溯，配置错误或服务不可用时健康检查能失败。
- 构建体积预算须按产物角色确定并可集中调整；硬性超限检查应报告文件、实际大小、适用阈值和定位方向，豁免须有明确范围。验证常规产物增长不会因无关文件共用单一阈值而阻断全部构建。
- 运行时资源地址依赖宿主、CDN 或公开全局变量时，将映射与基础路径集中维护，为调用方提供类型合同，并与部署说明保持一致；验证已知、近似及未知宿主的回退路径，以及脚本、样式和预加载资源的加载顺序与地址。
- 开发代理须明确目标选择、路径重写、TLS 校验、Host/转发头与认证信息的传播合同；配置项采用安全默认值，非默认行为说明原因。验证有无认证、异常 Host、目标不可达和各环境目标选择均符合预期。

## 测试策略与隔离

- 评审范围包含生产代码、测试代码、fixture、mock 和测试基础设施；测试辅助代码按测试目的与风险评审，重点检查真实性、误报漏报、确定性、隔离性和可维护性，不机械套用生产架构标准。
- mock 与 fixture 的响应形状须以真实接口合同为准，并与消费方的判断一致；成功标志、业务码、错误码、状态和数据存在性等关联字段必须形成可解释且经过验证的组合，反直觉组合须明确记录真实合同来源。动态 resolver、builder 或脚本生成的结果在交付给测试服务器前须通过完整运行时 schema 或等价守卫，除字段存在性外还应验证响应体结构、HTTP 状态范围、延迟等数值的有限性与非负约束；输入解析失败或输出非法时采用明确的默认场景或可诊断错误，不依赖外层偶然捕获。场景名称、文件名、说明和实际触发条件须一一对应。依赖当前时间的场景使用冻结时钟、相对日期生成器或有意覆盖边界的独立 fixture，不以会自然过期的历史日期充当长期默认数据；验证在不同执行日期和时区仍触发预期分支。慢响应、失败码、功能开关及其他调试行为使用可选择的独立场景或本地覆盖，不修改团队共享默认数据、延迟和结果；合并前验证默认 mock 仍是快速、确定且稳定的基线。每个样例应能从解析入口或测试到达，未接入的样例须说明用途或移除。存在默认样例时验证其能触发预期流程；移除默认样例或改变未命中处理时，明确记录代理、报错等回退路径并验证其行为，避免分支结构矛盾或隐式代理误导联调。
- fixture 只保留验证目标所需的最小代表数据；多个场景重复的大段文本、集合或嵌套对象通过类型化 builder、共享片段或生成脚本维护，生成结果仍须可追溯并符合真实合同。若目标是验证长文本、超大集合或性能边界，则单独命名该场景并记录规模依据。验证默认 fixture 的 diff 可审阅、无无关生产抓包载荷，精简后仍覆盖渲染、过滤和边界逻辑。
- 优先运行被测逻辑并断言用户可见行为、调用和状态；源码文本或正则断言仅作补充，必须使用标识符边界等稳定语义锚点、显式报告截取失败，并以正向锚点配合负向断言防止假通过。
- 测试替身放在被测合同的最窄边界：组件行为测试优先替换其调用的具体 API 或适配层，底层传输细节由请求层测试覆盖；替换聚合入口时使用 partial mock 保留未关心的真实导出，不用少量手写函数覆盖整个共享包。验证被测代码新增无关依赖时测试不会因导出缺失静默改变行为，真正受测的调用仍可精确断言。
- 测试引用源码或替换依赖时，使用包的公共入口、项目统一别名或集中 setup，不硬编码 `node_modules` 布局、包内部构建文件及深层相对解析路径；别名须同步测试运行器与类型配置。验证编辑器、类型检查、测试和不同包管理器安装布局解析到同一合同目标，目录移动或依赖升级不会导致成批替身失效。
- 每个受影响的独立分支都要有直接的正向用例；多条件共同决定是否调用外部服务时，列出有效条件组合并分别断言应调用与不应调用。按变更合同覆盖关键输入缺失、成功、失败、降级、重试、并发去重、取消或卸载中断、状态切换与安全边界；验证取消后无误报或残留状态，相邻分支的负向断言不能替代目标分支验证。
- 测试执行关键交互或读取关键目标前，先用会失败的断言确认目标存在且唯一，再触发动作；不得用可选链、空数组遍历或宽松选择器把“目标未渲染”变成无操作而静默通过。验证删除、改名或重复渲染目标时用例会明确失败，并优先通过可访问名称或稳定测试标识定位。
- 样式只有在属于验收合同时才断言，并限制为最小语义关键集；复用现有设计 token 或语义常量，但不为方便测试反向制造生产抽象。
- 测试清理优先调用被测对象真实的 `unmount`、`dispose` 或 `cleanup`；直接清空全局 DOM 仅作不遮蔽泄漏的兜底。全局对象替身使用测试框架可自动还原的 spy 或 stub；依赖在初始化时读取全局对象时，应在导入或挂载前安装替身，并验证用例间无残留状态。交互目标优先按可访问名称、文本或稳定测试标识定位，避免依赖元素位置。
- router、store、query client、事件总线等有导航历史或内部缓存的运行时对象，测试中按用例创建新实例并使用内存实现；必须复用单例时，在 `beforeEach` 和 `afterEach` 中显式恢复完整初始状态，不能只把当前页面推回某个路径而保留历史、守卫或订阅。验证随机顺序、单独运行及重复运行用例结果一致。
- 注册表、路由表或权限表测试优先验证唯一性、命名规范、必需元信息、懒加载及关键兼容项等不变量，再对高风险条目做精确合同断言；仅当完整列表本身就是冻结的对外合同才复制整表快照。验证新增合法条目无需同步维护与风险无关的长数组，同时重复名称、非法路径和缺失元信息仍会明确失败。
- 跨页面、跨版本、存储交接或特定浏览器、设备运行环境相关的变更，按失效风险补充契约测试、集成/E2E 或目标环境回归；影响 DOM 或可访问树语义的 CSS 用法也须在目标内核验证，单元测试不得替代真实边界与兼容链路验证。

## 交互质量与观测

实现和评审交互入口时，逐项确认：

- 可点击入口承载曝光、点击或转化目标时，按项目既有规范提供可区分的曝光与点击观测，验证事件名称、参数、触发时机及去重；观测失败不得阻塞主交互。
- 请求与响应日志默认脱敏 Cookie、Authorization、令牌、个人信息及其他敏感字段；正文记录采用关闭或摘要优先、显式开关开启，并设置单条长度与总缓冲上限，不能为打印日志无界缓存流式响应。验证大响应不会造成显著内存增长或刷屏，压缩、解析失败和截断仍保留可定位的结构化元数据。
- 交互所需关键数据缺失时，先按合同禁用或隐藏入口，或提供安全的失败反馈；验证空数据不能进入依赖完整数据的后续流程。
- 对外可达的生产路由、菜单或深链只能展示来自真实合同的数据，或明确标识且获准的空态/占位态；演示数据、伪造身份或订单信息、未实现的主操作必须隔离在开发环境、Storybook 或专用 mock 场景，未完成页面在生产入口启用前应由 feature flag、权限或路由注册门禁阻断。验证生产构建直接访问入口时不会显示看似真实的假数据，也不会暴露无反馈的主要按钮。
- 按钮、步骤说明、成功反馈和辅助文案须准确描述当前模式实际执行的动作与对象；同一组件支持多种目标时，由明确的语义参数或模式配置文案，不能沿用与真实行为不符的历史描述。验证用户依据文案可预期实际复制、跳转、提交或下载的内容。
- 交互控件使用原生可交互语义，提供可见文本或 `aria-label` 作为可访问名称，并验证键盘聚焦与触发行为。
- 受控选择组件以值变化事件或双向绑定合同上报状态，不用原始点击事件推断选择结果；校验和状态归属集中在单一层级。验证键盘操作、重复选择、禁用项及程序化更新与指针点击得到一致结果。
- overlay、popup、sticky、fixed 主操作等叠层遵循项目 z-index token 或层级约定；多个独立条件控制同一区域时，显式定义互斥、优先级或共存布局，并测试条件同时为真的组合，验证视觉层级、点击区域及唯一主操作符合合同，不以任意高值规避冲突。
- 重复的尺寸、间距和层级值复用项目现有 design token 或 CSS 变量；设计合同要求的特殊固定值注明来源和适用视口。响应式宽度与居中优先采用 `max-width`、`inset`、自动外边距等流式约束，并在目标视口验证，避免由固定负边距和连续断点补丁维持布局。
- 依赖 DOM 几何的滚动、定位或高亮交互，在目标出现、渲染提交及进入过渡完成后测量；异步目标应按可观察条件等待并设置超时或取消上限，不用固定延迟猜测完成时机。内容、字体、容器或视口变化时重新测量，一次性触发标记在成功或终止后按合同清理；验证慢加载、目标缺失及返回或刷新时不会使用过期坐标或重复触发。

## 变更元数据

提交或合并前，逐项确认：

- 以实际 diff 和当前任务核对 commit message、PR 或合并说明及任务编号，确保目的、范围和关联可追溯；错配须在合并前修正或留下明确更正记录。amend、rebase、force 等历史改写仍遵守既有 Git 授权边界。
- PR 与提交只包含目标改动；合并前盘点工作区未提交内容及生成文件，将无关变更拆分或明确排除，并以最终 diff 验证评审范围干净。
- 评审材料须包含支撑核心行为的实现、类型与测试变更；因生成、拆分或比较基线而未出现在当前 diff 的关键文件，应提供可定位版本和必要说明。验证评审者无需依赖测试或描述猜测未展示的实现。
- 修改函数返回值、环境映射、默认行为或兼容边界时，同步更新相邻 JSDoc、注释、README、示例和配置说明；验证文档描述可由当前实现或测试直接证实，不保留与代码相反的旧说明。
- PR 测试说明记录实际执行的命令、结果和未覆盖边界；未执行时明确原因与后续验证责任，不能把“等待 CI”表述为已通过。合并前优先补齐与风险相称的自动化检查或真实联调证据，使评审结论建立在可复现结果而非计划上。
- 新增强制性仓库规范时，明确适用范围、判定条件、例外及记录方式，并优先用 lint、类型、测试、schema 或提交门禁自动执行；人工检查只保留给无法稳定自动判定的语义，并提供可复现的验收步骤。验证规则能在违规示例上失败、在合法与例外示例上通过，且不会与现有代码、测试或工具链形成无法执行的冲突。
- 本次变更确认废弃的注释代码或停用实现应直接删除，由版本历史承担追溯；验证当前文件只保留仍有效的说明和实现，不顺手清理无关旧代码。
