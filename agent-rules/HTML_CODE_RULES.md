# HTML 代码规范

新增、修改或评审 `.html`、`.htm`、生成 HTML 的模板文件，以及 Vue 单文件组件的 `<template>` 时遵循本规范。项目已有 HTML lint、框架编译器、组件库和设计系统约束优先；本文件规定工具配置未完整表达的 HTML 语义、可访问性和文档结构约束。

模板表达式中的 JavaScript/TypeScript 由 [JavaScript 与 TypeScript 代码规范](/Users/chenjianwei2/.codex/agent-rules/JS_TS_CODE_RULES.md) 负责，动态 HTML、安全边界、交互测试和交付验证由 [代码评审与工程约束](/Users/chenjianwei2/.codex/agent-rules/CODE_REVIEW_RULES.md) 负责，不在本文件重复维护。

## 1. 文档基础

- 独立页面使用 `<!doctype html>`，根元素声明准确的 `lang`；字符编码使用 `<meta charset="utf-8">` 并放在文档头部前部。
- 移动端页面按产品合同配置 viewport；默认使用 `width=device-width, initial-scale=1`，需要禁止缩放时必须有明确业务和无障碍依据。
- 每个页面提供准确且可区分的 `<title>`；页面公开分享、搜索收录或安装能力所需的 description、canonical、Open Graph、manifest 等元数据按产品合同提供，不添加无消费者的模板字段。
- `head` 只放元数据、资源声明和确有必要的初始化内容；可延后的脚本使用模块默认延迟或 `defer`，避免阻塞首屏解析。
- HTML 保持有效嵌套和完整闭合，不依赖浏览器自动纠错维持 DOM 结构；最终判断以浏览器解析后的 DOM 为准。

## 2. 语义结构

- 使用最能表达内容和行为的原生元素，不用通用 `div`、`span` 或视觉样式代替标题、段落、列表、按钮、链接、表格及表单控件。
- 页面使用清晰的 landmark：`header`、`nav`、`main`、`aside`、`footer` 按真实职责出现；同页通常只有一个主要 `main`，重复导航通过可访问名称区分。
- 标题层级反映内容结构，不按字号选择 `h1` 至 `h6`；每个 sectioning 区域在需要时提供可识别标题，不为视觉效果跳过层级。
- 顺序性内容使用 `ol`，无序集合使用 `ul`，术语与定义使用 `dl`；不使用 `<br>` 堆叠间距或模拟段落。
- 仅在数据具备二维表格关系时使用 `table`；布局使用 CSS。数据表提供 `caption` 或等价可访问名称，表头使用 `th` 并通过 `scope` 或 headers 关系明确关联。

## 3. 标记与属性

- 标签和原生属性使用小写；普通 HTML 属性使用双引号，布尔属性按存在即真的语义书写，不同时提供互相矛盾的属性与 ARIA 状态。
- `id` 在最终 DOM 中必须唯一且稳定，只用于真实的标签关联、锚点或脚本合同；样式优先使用 class，测试优先使用专用测试属性或可访问名称。
- 自定义元数据使用语义明确的 `data-*`；未知属性、拼写错误属性和失效的历史属性应删除，不让浏览器容错掩盖错误。
- class 描述组件、状态或设计 token，不把随机资源名、后端字段或脆弱 DOM 位置作为长期语义；遵循项目已有 CSS/Tailwind 命名和排序工具。
- 样式和行为分别由 CSS 与脚本或框架事件处理承担；不新增内联 `style`、`onclick` 等事件属性，遗留环境确需使用时记录 CSP 与兼容依据。
- HTML 注释只说明无法由结构表达的集成、兼容或生成约束，不保留注释掉的大段旧标记。

## 4. 交互元素

- 执行动作使用原生 `button`，导航使用具有真实目标的 `a`；不使用 `a href="#"`、空链接、`div` 或 `span` 模拟按钮。
- `button` 显式声明 `type="button"`、`submit` 或 `reset`，避免在表单中依赖默认提交行为；禁用状态使用原生 `disabled`，仅视觉禁用时不能继续响应点击或键盘操作。
- 链接的 `href` 必须可用且与展示目的相符；新窗口打开时向用户提供可预期提示，并使用 `rel="noopener noreferrer"` 或平台等价保护。
- 原生控件保持默认键盘语义和焦点能力；确实没有合适原生元素时，自定义控件必须提供正确 role、可访问名称、状态、键盘操作和可见焦点，并验证与原生行为一致。
- 不使用正的 `tabindex` 重排焦点；DOM 顺序应与视觉和阅读顺序一致。暂时移出焦点流时同时确认控件不可见或不可操作。
- 点击区域内避免嵌套另一个独立交互控件；需要复合交互时拆分明确的焦点目标和事件边界。

## 5. 表单

- 每个可编辑控件都有持久可见的 `label`，通过 `for`/`id` 或组件合同关联；placeholder 只提供示例或提示，不能代替标签。
- 使用与数据含义匹配的 `type`、`name`、`autocomplete`、`inputmode`、`min`、`max`、`step` 等原生能力，并与服务端验证规则保持一致。
- 同组选项使用 `fieldset` 与 `legend`，或提供等价的可访问分组；单选、复选与开关的标签点击应操作对应控件。
- 必填、禁用、只读和无效状态使用正确的原生属性；ARIA 只补充原生语义缺口，不用 `aria-*` 替代可用的 HTML 属性。
- 校验失败时提供具体错误文本，将错误与控件通过 `aria-describedby` 或组件等价机制关联，并把焦点或错误摘要引导到可恢复位置；颜色不能作为唯一错误提示。
- 提交期间防止重复提交但保留状态反馈；错误后恢复控件可操作性，不清除用户仍可修正的输入。

## 6. 图片、图标与媒体

- 信息图片提供准确简洁的 `alt`；纯装饰图片使用空 `alt=""` 并避免进入可访问树，不能省略 alt 让文件名被朗读。
- 图标按钮必须有可访问名称；随文字出现的装饰图标对辅助技术隐藏，表达状态的图标同时提供文本或 ARIA 状态。
- 图片声明可获得的固有 `width` 和 `height` 或使用稳定纵横比，避免加载时布局偏移；非首屏图片按实际场景使用原生懒加载。
- 响应式图片按需要使用 `srcset`、`sizes` 或 `picture`，不向小视口无条件传输远超展示尺寸的资源。
- 音视频提供用户可控制的播放方式；非必要不自动播放，自动播放必须静音并符合平台策略。承载关键信息时提供字幕、文本替代或产品合同要求的辅助内容。
- iframe 提供可识别 `title`，按最小权限配置 `sandbox`、`allow` 与 referrer policy；外部嵌入内容不得默认获得不需要的能力。

## 7. 可访问性

- 优先使用原生语义，再使用 ARIA；ARIA role、属性和值必须符合规范且与实际交互状态同步，不添加无效、拼写错误或互相冲突的属性。
- 所有交互入口拥有来自可见文本、`label`、`alt` 或 `aria-label`/`aria-labelledby` 的稳定可访问名称；名称应描述动作或目标，不只写“点击”“更多”。
- 动态状态、校验结果和异步完成提示按重要性使用合适的 live region；避免频繁更新造成重复朗读。
- 对话框、菜单、标签页、折叠面板等复合组件优先使用项目已验证的组件库；自定义实现必须覆盖焦点进入、焦点循环或返回、Escape、键盘导航和状态关联。
- 隐藏内容根据目的选择 `hidden`、CSS、`aria-hidden` 或 inert；不可见但仍可聚焦、可点击的元素属于错误状态。
- DOM 顺序、键盘顺序和视觉顺序保持一致；修改布局后验证键盘、读屏与缩放场景，而不只检查鼠标点击。

## 8. Vue 与模板标记

- Vue `<template>` 使用与静态 HTML 相同的原生语义和可访问性要求；组件标签不能成为绕开最终 DOM 语义检查的理由。
- 模板表达式保持简单，只做读取、轻量格式化和事件参数传递；复杂条件、连续三元、排序过滤及有副作用计算移到 script 中的 computed 或具名函数。
- `v-for` 使用稳定且唯一的 `:key`，不使用数组索引或可变展示文本；过滤列表时先派生数据，避免在同一元素混用 `v-for` 与 `v-if`。
- `v-if` 用于真实创建/销毁，`v-show` 用于需要保留状态的频繁显隐；选择时考虑组件生命周期、表单状态和可访问树，而不只考虑代码更短。
- 自定义组件的事件、属性和双向绑定遵循组件公开合同；不要把未知原生属性无意透传到根元素，必要时显式管理 attrs。
- `v-html` 仅用于经过统一可信清洗边界的富文本；纯文本使用插值。拼接过的局部字符串也必须整体重新清洗，不能假设其中一部分已经安全。

## 9. 安全与外部内容

- 用户、接口、缓存和 URL 提供的文本默认按纯文本渲染；需要富文本时遵循全局评审规则中的白名单清洗合同。
- 外部链接、表单 action、iframe src、图片和媒体地址在绑定前经过协议及目标校验；模板转义不能替代 URL 安全校验。
- 不把令牌、个人信息和敏感业务数据写入 HTML 注释、data 属性、隐藏表单或可被页面源码读取的静态标记。
- 内联脚本、内联事件和动态代码执行必须符合项目 CSP；不得为绕过 CSP 添加 `unsafe-inline`、`unsafe-eval` 或等价放宽。
- 第三方脚本和嵌入资源只加载完成页面功能所必需的来源，并遵循项目的版本固定、同意管理、完整性和环境配置策略。

## 10. 性能与资源加载

- 首屏关键 CSS、字体、脚本和媒体按实际依赖加载；非关键资源延后，不为看似优化而添加无依据的 preload、preconnect 或 priority。
- script 标签明确加载语义：ES module 使用 `type="module"`，传统非关键脚本使用 `defer`；只有确实相互独立且不依赖执行顺序时使用 `async`。
- 避免在模板中重复内联大段 SVG、JSON、样式或相同静态内容；按复用和缓存需求选择组件、外部资源或构建期生成。
- 字体声明实际使用的格式和字重，避免预加载未使用资源；图像和媒体优化遵循静态资源及构建预算规则。
- 页面不能依赖缺失资源、同步远程脚本或无超时的第三方内容才能完成基本交互；关键功能提供明确降级。

## 11. 验证

- 完成修改后运行项目已有的格式化、HTML/Vue lint、模板类型检查和生产构建；独立文档可使用项目认可的 HTML validator。
- 检查最终渲染 DOM，而不只检查源模板：确认无重复 id、无未知属性、标签关联正确、资源可解析且条件渲染没有制造非法嵌套。
- 对受影响交互至少验证键盘操作、焦点可见性、可访问名称、禁用与错误状态；重要页面按项目要求补充读屏、缩放和目标 WebView/浏览器验证。
- 验证失败时修正结构或合同，不通过删除语义属性、关闭 lint 或增加无依据 ARIA 让检查表面通过。
