# JavaScript 与 TypeScript 代码规范

新增、修改或评审 `.js`、`.jsx`、`.mjs`、`.cjs`、`.ts`、`.tsx`、`.mts`、`.cts`、`.vue` 文件时遵循本规范；在 Vue 单文件组件中，本规范适用于 `<script>`、`<script setup>`、模板表达式及其调用的 JavaScript/TypeScript 逻辑。项目已有 ESLint、Prettier、TypeScript、Vue 编译器与运行时约束优先；本文件规定项目配置未完整表达的语言级约束。

## 1. 语言与运行时

- 新代码优先使用项目已经支持的 TypeScript；维护 JavaScript 时保持现有构建合同，不为单次修改引入新的转译链。
- 采用语法或 Web、Node API 前核对项目 `engines`、`tsconfig`、构建目标和实际运行环境；需要兼容旧环境时使用项目既有适配层。
- 使用 ESM 或 CommonJS 时遵循所在包的模块制式，不在同一模块中混用 `import`、`require` 和不同导出语义。
- 不修改原生对象原型，不依赖未声明的全局变量；浏览器、Node 或宿主注入的全局能力须在类型和运行时两侧显式建模。

## 2. 变量与命名

- 默认使用 `const`；只有确需重新赋值时使用 `let`，不使用 `var`。
- 变量、函数和属性使用能描述业务语义的 `camelCase`，类型、类和组件使用 `PascalCase`，真正跨调用保持不变的常量使用 `UPPER_SNAKE_CASE`；遵循项目对文件名和导出名的既有约定。
- 布尔值使用 `is`、`has`、`can`、`should` 等可直接判断真假的命名；集合使用复数名，时间、金额、尺寸等数值在名称或类型中体现单位。
- 状态码、类型码、路由名、协议字段、阈值和重复领域字面量使用最小合理作用域的具名常量；一次性且语义显然的局部字面量无需抽象。
- 不用同一变量承载不同类型或不同生命周期阶段；状态发生语义变化时创建新变量或使用可辨识状态模型。

## 3. 值、比较与转换

- 默认使用 `===` 和 `!==`；外部接口存在字符串与数字混用时先在边界归一化，再进入业务判断，不依赖宽松相等。
- 使用 `String`、`Number`、`Boolean` 或领域解析函数显式转换；数值转换后用 `Number.isFinite` 或合同允许的等价校验确认结果，`parseInt` 必须传入进制。
- 区分 `null`、`undefined`、空字符串、零和空集合的业务语义；只有合同明确等价时才使用宽泛真值判断或 `??` 合并。
- 可选链只用于合同允许缺失的路径；必需值、必需交互目标和必须执行的函数先显式校验，不能用 `?.` 将缺陷变成静默跳过。
- 字符串拼接优先使用模板字符串；构造 URL、查询参数、HTML、SQL 或其他结构化内容时使用对应的结构化 API，不能把模板字符串当作转义机制。

## 4. 函数与控制流

- 一个函数只承担一个可命名职责；解析、校验、转换、副作用和展示适配达到独立职责时分层处理，不按行数机械拆分。
- 优先使用提前返回减少嵌套；条件复杂时提取有业务含义的谓词，避免连续三元表达式和依赖求值副作用的短路技巧。
- 参数超过合理阅读范围或多个参数属于同一概念时使用具名对象；布尔参数无法从调用处读出含义时改为选项对象或可辨识模式。
- 默认不修改调用方传入的对象和数组；确需原地修改时通过函数名、类型和注释明确所有权，并限制在局部边界。
- 公共函数的返回值保持单一语义；多种结果使用可辨识联合、结构化结果或明确异常，不混用用户文案、哨兵字符串、`null` 和正常数据表示状态。
- 删除消费者时同步删除仅为其服务的计算、分支、导入和异常处理，不保留无可观察作用的代码。

### 函数 JSDoc

- 新建函数时，在函数定义正上方添加 JSDoc；第一行说明函数职责，并包含完整的 `@param` 与 `@returns`，无参数时省略 `@param`。
- 对象参数使用 `@param` 展开需要说明的属性；文档中的参数名、可选性、返回结构必须与真实类型和运行时行为一致。
- 函数可能抛出需要调用方处理的异常时使用 `@throws`；非显然用法使用 `@example`；废弃 API 使用 `@deprecated` 指明替代方案。JavaScript 中的独立复杂类型可按需使用 `@type` 或 `@typedef`。

```typescript
/**
 * 根据用户 ID 获取用户名称
 *
 * @param userId - 用户的唯一标识符
 * @param options - 请求配置项
 * @param options.timeout - 超时时间（毫秒）
 * @param options.retry - 是否重试
 * @returns 用户姓名
 */
async function getUserName(
  userId: string,
  options: { timeout: number; retry?: boolean },
): Promise<string> {
  // ...
}
```

## 5. TypeScript 类型

- 对新增或修改代码保持项目严格模式通过；不得用关闭规则、扩大类型或批量断言掩盖真实类型错误。
- 优先让 TypeScript 推断局部变量；公共导出、共享数据模型、回调合同及可能产生歧义的函数显式声明类型和返回值。
- 外部数据、反序列化结果和捕获的异常先视为 `unknown`，通过类型守卫、schema 或明确判定收窄后使用；不使用裸 `any` 扩散未知值。
- 类型断言只允许出现在无法由编译器推导但已有运行时证据的边界，并就近说明证据；禁止用 `as unknown as T`、非空断言或过宽索引签名绕过建模与校验。
- 有限状态、互斥模式和成功/失败结果使用可辨识联合并进行穷尽检查；新增成员后，遗漏分支应触发编译错误或明确失败。
- 核心接口模型列出真实字段及可选性；`Record<string, unknown>`、索引签名和开放对象仅用于确有动态键的边界，不能覆盖稳定业务字段。
- 多种原始类型仅保留在兼容边界，进入领域逻辑前归一化为单一内部类型；不让 `string | number | null` 等宽联合沿调用链扩散。
- 使用 `readonly`、只读数组或不可变结构表达不应由调用方修改的数据；泛型必须表达输入与输出之间的真实关系，不为减少重复书写而引入无约束泛型。
- 类型导入使用 `import type`；类型和值同名或跨包导出时保持入口清晰，避免由类型引用意外引入运行时代码。

## 6. JavaScript 类型约束

- 不能迁移为 TypeScript 的 JavaScript 文件，对公共函数、复杂对象和宿主全局使用准确 JSDoc，使编辑器和类型检查能验证调用合同。
- JSDoc 类型与运行时返回结构保持一致；禁止用宽泛 `{Object}`、`*` 或不真实的非空类型掩盖动态数据。
- 运行时数据仍需校验，JSDoc 只提供静态提示，不能替代解析、类型守卫或 schema。

## 7. 异步与错误处理

- Promise 必须被 `await`、返回、组合或明确标记为有意忽略；不得产生无人观察的拒绝。
- 使用 `async`/`await` 保持主流程清晰；只在封装回调或事件 API 时手写 `new Promise`，并保证成功、失败、取消和超时均只 settle 一次。
- 相互独立的任务根据合同并发执行；有依赖的任务按顺序执行。并发时明确失败策略、结果顺序和取消传播，不用 `forEach(async () => ...)` 等无法等待的写法。
- `catch` 中先把错误视为 `unknown` 并收窄；只捕获当前层能补充上下文、降级或恢复的错误，无法处理时保留 cause 重新抛出。
- 不使用空 `catch`；预期取消可以静默，但必须通过错误类型、状态码或取消信号与真实故障区分。
- `finally` 仅处理无论成功失败都必须执行的清理，不在其中返回值或抛出新错误覆盖原结果。

## 8. 对象、数组与集合

- 使用 `map`、`filter`、`find`、`some`、`every`、`reduce` 等与意图一致的操作；需要提前终止或包含复杂副作用时使用普通循环。
- 不在 `map` 中只做副作用，不用 `reduce` 隐藏简单循环；选择可读性最高且能表达终止条件的结构。
- 列表关联、去重和渲染使用稳定唯一键；不以数组索引或可能重复的展示文本作为跨更新身份。
- 展开对象前确认字段传播符合合同；构造接口载荷、存储数据和跨页面状态时显式挑选字段，不直接扩散整个运行时对象。
- 对大集合避免循环内重复查找和隐式二次复杂度；先建立 `Map`、`Set` 或索引的前提是数据规模和热点路径确实需要。

## 9. 模块与依赖边界

- 从包的公共入口导入，不穿透 `node_modules`、构建产物或未承诺稳定的内部路径；同一仓库使用项目统一别名或包导出映射。
- 模块顶层只执行确定、安全且与导入环境兼容的初始化；读取可变环境、访问 DOM、发请求、注册监听器等副作用放入显式入口。
- 避免循环依赖；共享常量、类型和纯函数下沉到不依赖上层模块的位置，不能通过运行时导入顺序维持正确性。
- 默认使用命名导出以便检索与重构；项目或框架已有默认导出约定时保持一致，不为风格统一制造无关 diff。
- 新增依赖前确认现有平台或工具函数不能满足需求，并评估包体积、运行环境、维护状态和许可证；依赖只在实际使用它的包中声明。

## 10. 注释与可验证性

- 注释解释业务原因、外部合同、兼容限制和非显然取舍，不复述代码；临时兼容需注明来源、适用范围和移除条件。
- `TODO`、`FIXME` 必须包含可追踪任务或明确完成条件，不能代替当前变更必须实现的逻辑。
- 完成修改后运行项目已有的格式化、lint 和类型检查；按影响范围运行测试与构建。不得通过禁用规则或更新快照把失败直接变成通过，验证结果须与实际执行一致。
