# Codex 模型路由

按任务复杂度选择模型，不要求用户手动指定。任务复杂度由风险、影响范围和不确定性决定，不能只看文件数量或代码行数。

| 任务级别 | 判断依据 | 新任务或委派时的模型与推理强度 | 执行方式 |
| --- | --- | --- | --- |
| 简单 | 目标明确、低风险的查询、提取、分类或格式转换 | `gpt-5.6-terra`，`low` | 当前主代理直接完成；只有需要独立支撑任务时才委派 `quick_worker`。 |
| 常规 | 范围明确的普通代码修改、局部 Bug 修复、测试补充或普通评审 | `gpt-5.6-sol`，`medium` | 委派 `standard_worker`。 |
| 复杂 | 涉及安全、数据损失、数据迁移、公共契约、跨模块修改、长期不明的根因或高回归风险 | `gpt-6-astra`，`high` | 委派 `deep_worker`。 |

- 无法确定任务等级、没有匹配的路由或目标模型不可用时，默认使用 `gpt-5.6-sol`、`medium` 先核对事实；确认任务等级后再按上表选型。已确认的复杂风险直接使用 `gpt-6-astra`、`high`。
- 用户明确指定模型时优先遵循；若当前工具或执行环境不支持，应说明情况，再使用上述默认模型；默认模型也不可用时使用当前可用模型并如实说明。
- 当前会话的主代理模型不能由 Markdown 规则自动切换。直接处理的任务沿用当前会话模型；创建子代理或新任务时按上表选型，不能为省模型而强制增加无必要的委派。
- `~/.codex/agents/*.toml` 中的 `model` 与 `model_reasoning_effort` 固定命名子代理的实际配置；配置变更可能要在新任务或新会话中重新加载，不能把当前会话的角色元数据当成生效证据。
