# README 同步规则

代码修改完成且相关验证通过后、向用户交付前，执行以下步骤。

## 1. 确认 README

- 以当前项目或版本库根目录为准检查 `README.md`，不能按命令当前目录猜测项目根目录。
- 根目录不存在 `README.md` 时，不自动创建；在交付结果中说明未发现该文件。
- `README.md` 是生成文件时，修改其权威来源并按项目既有方式重新生成，不直接维护会被覆盖的产物。

## 2. 同步本次变更

- 对照最终代码 diff，逐项检查 README 中与本次变更相关的功能、目录结构、安装、启动、构建、测试、配置、环境变量、接口、参数、示例、兼容性和限制说明。
- 更新所有受影响内容，删除已经失效的描述，并补充用户正确使用本次变更所必需的信息；不能只追加新内容而保留互相冲突的旧说明。
- 只写当前代码、配置或验证结果能够证明的事实，不根据计划、猜测或未完成实现提前描述能力。
- 保持 README 原有语言、章节结构、术语和格式，仅调整本次变更涉及的内容；无关内容不顺手重写。

## 3. 核对准确性

- 将 README 中新增或修改的命令、路径、文件名、脚本名、配置键、环境变量、默认值、接口和示例逐项与当前仓库核对。
- 检查相对链接和引用文件确实存在；重命名或删除内容后，搜索 README 中是否仍残留旧名称、旧路径或旧用法。
- README 中声明某条命令或流程可用时，应使用当前项目要求的环境实际执行，或引用本轮已经成功完成的等价验证；未验证的内容不得写成已确认事实。
- README 修改后重新检查文档 diff。发现无法确认真伪的描述时，继续查证、修正或删除；不能在已知 README 仍含错误时交付。

## 4. 交付说明

- 最终回复说明是否检查了根目录 `README.md`、同步了哪些对应内容，以及采用了什么方式验证准确性。
