# Codex 任务路由

每次收到任务时，根据风险、影响范围和不确定性一次性确定任务级别、执行代理、模型与推理强度，不能只按文件数量或代码行数判断。

| 任务级别 | 判断依据 | 执行代理 | 模型与推理强度 |
| --- | --- | --- | --- |
| 简单 | 不修改代码，且目标明确、低风险的查询、提取、翻译、分类或格式转换 | 当前主代理直接完成；仅有可独立验收的低风险只读支撑工作时使用 `quick_worker` | 新建任务或委派时使用 `gpt-5.6-terra`、`low` |
| 常规 | 范围明确的普通代码修改、局部 Bug 修复、测试补充或普通代码评审 | 必须委派给 `standard_worker` | `gpt-5.6-sol`、`medium` |
| 复杂 | 涉及安全、数据损失、数据迁移、公共契约、跨模块修改、长期不明的根因或高回归风险 | 必须委派给 `deep_worker` | `gpt-6-astra`、`high` |

## 路由补充规则

- 难以判断任务级别、没有匹配路由或目标模型不可用时，先使用 `gpt-5.6-sol`、`medium` 只读核对事实；确认风险后再按上表执行。已确认的复杂风险直接使用 `deep_worker`。
- `quick_worker` 只承担可独立验收的低风险只读支撑任务，不能替代 `standard_worker` 或 `deep_worker` 完成代码修改。
- 独立 verifier 仅用于高风险或大范围改动；普通任务不强制。子代理完成后，主代理必须检查修改、证据和验证结果，再向用户汇总。
- 用户明确指定模型时优先遵循；当前工具或执行环境不支持时，说明原因后使用表中对应模型。对应模型也不可用时，使用当前可用模型并如实说明。
- 当前会话的主代理模型不能由 Markdown 规则动态切换。主代理直接处理的任务沿用当前会话模型；创建子代理或新任务时使用表中配置，不能为切换模型而增加无必要的委派。
- `~/.codex/agents/*.toml` 中的 `model` 与 `model_reasoning_effort` 决定固定命名子代理的实际配置。配置变更可能需要新任务或新会话重新加载，不能把当前会话的角色元数据当作生效证据。
