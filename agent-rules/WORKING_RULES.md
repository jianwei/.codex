# 通用工作原则

这些规则用于减少常见的代码实施错误，并与项目特定约束一起使用。对简单任务按实际情况精简流程。

## 1. 编码前先确认

- 明确影响实现的假设、边界和取舍；先从现有代码与证据中消除不确定性。
- 存在多种会改变结果的解释且无法从上下文判断时，及时向用户说明并询问；可独立推进的部分继续完成。
- 有更简单的方案时说明原因，并在必要时提出不同意见。

## 2. 保持简单

- 只实现请求范围内的功能，不做推测性扩展。
- 不为单次使用预先抽象，不增加未要求的灵活性或配置项。
- 不为实际不可能发生的情况增加错误处理。
- 如果 50 行足够解决问题，就不要写 200 行。

## 3. 精确修改

- 只修改完成任务所需的内容，不顺手调整相邻代码、注释或格式。
- 遵循文件现有风格；发现无关死代码时说明即可，不要擅自删除。
- 清理本次修改造成的未使用 import、变量或函数；不清理已有的无关死代码。
- 每一处改动都应能追溯到用户请求。

## 4. 以可验证结果推进

- 开始多步骤任务时，简述步骤及各步骤的验证方式。
- 将目标转为可验证条件：例如输入校验覆盖非法输入，Bug 修复能复现并验证修复，重构前后既有测试保持通过。
- 验证失败时继续排查与修复，直至达到任务目标或出现需要用户输入的实际阻碍。
