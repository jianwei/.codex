# 页面迁移

以来源页面的真实运行行为为基线，以可追溯的对照表推进迁移。用户明确指定的设计稿、目标约束和允许差异优先于来源页面；除此之外，不擅自增删或改进用户可见行为。

## 工作流

### 1. 建立完整对照表

- 逐页追踪路由入口、路径参数、查询参数、子组件、状态、交互、跳转、接口、Mock、静态资源、埋点和宿主环境分支。
- 沿实际调用、赋值、请求和渲染链确认依赖，不以顶层页面文件代表完整范围。
- 为每一项记录来源证据、迁移去向、验证方式；确实不适用的项目记录依据。
- 将现有未提交内容视为他人工作，只纳入迁移所需范围。

完成条件：对照表中的每一项都有迁移去向或不适用证据，且本批页面范围与用户要求一致。

### 2. 固定来源基线

- 在代表性数据、目标视口和各适用宿主条件下运行来源页面，记录页面截图、关键 DOM、网络请求、控制台输出和导航行为。
- 覆盖初始、加载、成功、空数据、业务失败、传输失败、弹层、提交、取消和返回等实际存在的状态。
- 来源页面无法运行时，使用源码、接口合同、既有测试和可用运行证据交叉还原，并明确无法现场确认的边界。

完成条件：后续 UI、逻辑和数据迁移所需的关键状态均有可复现基线或已注明证据缺口。

### 3. 迁移路由合同

- 按目标代码库的既有路由约定落地；只有用户明确允许时才改变 URL。
- 保留路径参数、查询参数、编码规则、页面间数据传递、历史记录以及跳转和替换语义。
- 确保每个页面可独立直达和刷新，不依赖上一页面遗留的内存状态。

完成条件：每个入口均通过直达、刷新、前进后退和页面间导航验证，所有参数与历史行为符合对照表。

### 4. 等价还原 UI

- 逐页、逐组件还原结构、文案、层级、尺寸、间距、字体、颜色、图标、加载态、空态和弹层。
- 存在指定设计稿时，仅调整设计稿中已有元素；未获授权时，不新增、删除或改进用户可见元素。
- 遵循目标代码库现有的样式、组件、目录和可访问性约定，不建立平行实现体系。
- 使用相同数据、视口和宿主条件对来源页与目标页进行截图和实际 DOM 对比。

完成条件：所有可见状态均已对比，页面结构和视觉无未说明差异，也没有未授权的新元素。

### 5. 等价迁移业务逻辑

- 保留初始化、数据转换、条件渲染、校验、搜索、弹层、提交、跳转、返回、加载、失败和取消语义。
- 保留来源页面已有的不同容器、嵌入方式和普通浏览环境分支，以及标题、状态栏、关闭和返回合同。
- 为请求、监听、计时器和其他异步资源建立与页面生命周期对称的取消与清理，不改变用户可见结果。
- 保持路由入口轻量，并依照目标代码库的现有边界组织复杂状态、数据适配和交互。

完成条件：对照表中的每个交互和条件分支均已实现并验证，宿主差异与生命周期行为没有遗漏。

### 6. 完整迁移接口与 Mock

- 迁移页面依赖的全部请求和本地运行数据，保持路径、方法、参数结构与编码、凭据策略、响应结构和业务成功判定一致。
- 同步迁移 Mock 或 fixture，使其覆盖真实数据规模、关键条件、搜索或过滤、空结果、业务失败和传输失败。
- 保证直达、页面间导航和关键交互在无远程依赖时仍能完整运行，不用单一简化成功响应替代原合同。

完成条件：每个请求都能追溯到目标实现和本地数据分支，成功、失败、空数据及关键条件均有可运行证据。

### 7. 闭环资源、埋点与运行约束

- 按目标代码库约定迁移或托管来源页写死的外部静态资源；接口动态返回的业务资源按原合同处理。
- 逐项迁移声明式和动态埋点，保持事件参数与触发时机；来源页无埋点时，以源码和运行检查为证据，不凭推测新增。
- 核对可访问语义、最终 DOM、网络请求、控制台和目标代码库明确禁止的实现形式。
- 清理仅由本次迁移造成的未使用内容，不格式化、覆盖或回退无关改动。

完成条件：资源、埋点、可访问语义和运行约束均与对照表及目标代码库一致，源码与运行时检查无遗漏。

### 8. 执行整体验收

- 按变更风险运行组件、接口、Mock 合同、集成或端到端测试，以及目标代码库定义的类型、静态、格式和生产构建检查。
- 在浏览器中复验直达、刷新、导航、关键交互、弹层、加载、空结果、失败恢复、最终 DOM、网络和控制台。
- 汇总实际执行的命令、结果、已确认差异和未覆盖边界；未满足完成门槛时继续修复或明确报告阻碍。

完成条件：下列完成门槛全部满足后，才可报告本批页面迁移完成。

## 完成门槛

- 对照表完整：每个路由、参数、组件、状态、交互、跳转、接口、Mock、资源、埋点和宿主分支都有目标实现或不适用证据。
- 路由完整：每个页面均可直达、刷新和页面间导航，参数编码、历史记录及宿主分支符合基线。
- 视觉完整：来源页与目标页已在相同数据、视口和宿主条件下完成对比，结构、文案、交互、弹层、加载和空结果无未说明差异。
- 逻辑完整：初始化、转换、条件分支、校验、搜索、提交、失败、取消、返回及异步清理均按来源合同运行。
- 数据完整：全部接口与本地数据分支可运行，并覆盖成功、业务失败、传输失败、空数据和关键条件；Mock 未用简化响应掩盖真实合同。
- 资源与观测完整：静态资源、埋点及其参数和时机均已核对，没有遗漏或凭推测新增。
- 运行约束完整：目标代码库约定、可访问语义、实际 DOM、网络请求和控制台均通过检查，无页面自身错误或未授权元素。
- 工程验证完整：风险相称的测试和目标代码库规定的类型、静态、格式及生产构建检查通过；实际命令、结果和未覆盖边界已如实报告。
